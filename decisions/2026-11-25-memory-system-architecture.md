# 决策记录：个人记忆与决策系统技术选型

## 1. 背景与核心问题
希望建立一个能辅助平时学习、定期复盘，并在不确定时辅助做决定的系统，放到 GitHub 仓库中由本地 Agent 根据后续发生的事情持续维护。需要决定初始采用什么样的工程形态。

## 2. 备选方案对比

| 方案 | 优点 | 缺点 / 风险 |
| :--- | :--- | :--- |
| **方案 A：Git + Markdown + `AGENTS.md` + 轻量巡检脚本（推荐）** | 零运维负担；Git 自带完整认知演进历史；本地 Agent 读写检索最直接；随时可用任意编辑器查看；后续可无损迁移。 | 没有花哨的图形化仪表盘。 |
| **方案 B：自建 Web 应用 + 数据库/向量库** | 界面定制化强，可做复杂检索。 | 前期开发与维护成本高，容易陷入“折腾工具而忘了记录和复盘本身”的陷阱。 |

## 3. 最终决定与理由
- **最终选择**：**方案 A（Git + Markdown + 本地 Agent 协议）**。
- **核心理由**：符合「先完成最小闭环，再谈优化」的原则；这是一个**双向门决策**，先把内容和复盘习惯沉淀下来，未来数据量大了随时可以在此基础上加脚本或检索层。

## 4. 预期结果与评判标准（供 `2026-12-25` 回看）
- **预期**：1 个月内能顺畅记录至少数次学习笔记、周复盘和真实决策，且没有因为格式繁琐而中断使用。
- **如果未达预期怎么调**：检查是哪个目录/模板太重，让 Agent 进一步简化流程。
